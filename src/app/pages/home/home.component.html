About this Project

Authify is a full-stack role-based access control (RBAC) system with a secure backend and a modern Angular frontend.

Frontend

Built with Angular 21 (Standalone Components)

  • Angular 21 standalone components with lazy loading
  • Role-based route guards (authGuard)
  • HTTP interceptor for automatic JWT token injection
  • Reactive forms with inline field-level backend error display
  • ChangeDetectorRef for instant UI updates on async data
  • Toast notifications for all user feedback
  • Permission checks on every Create / Update / Delete action
  • Responsive design with vanilla CSS design tokens

Backend

Built with Spring Boot 3 + Spring Security

  • JWT-based stateless authentication (access tokens)
  • Role-based access control: ADMIN, TEACHER, USER
  • Method-level and URL-level permission enforcement
  • Email OTP verification on registration
  • Forgot password flow with OTP via email
  • Password reset with token expiry validation
  • Audit fields on records: createdBy, updatedBy, timestamps
  • Clean RESTful API with structured error responses
  • Deployed on Render (free tier — cold start applies)

Pagination & Security

Different modules use different pagination strategies and access levels.

⊞

Student & Teacher

Offset-based (Default Pageable)
  • Uses Spring Data's default Pageable with page numbers
  • Supports search, sort, and filter query params
  • Navigate to any page via Prev / Next / page buttons
  • Page size: 9 records per page
🔒 Auth Required Login needed to view — role-based CRUD permissions
⇥

Staff

Keyset / Cursor-based
  • Uses keyset (cursor) pagination — no page numbers
  • "Load More" appends data, never replaces
  • Forward-only navigation via nextCursor
  • Size options: 20 / 50 / 100 records per load
🌐 Public No login required — anyone can view the staff list

Approval & Invitation Workflows

Two ways users join the platform — self-registration (with approval) or admin invitation.

Self-Registration → Approval

Admin / Teacher
  1. User registers on the Sign In page (Register tab)
  2. Account is created with status PENDING — login is blocked until approved
  3. Admin or Teacher visits Approvals page to see all pending users
  4. Clicking Approve activates the account and notifies user by email
  5. Clicking Reject (with confirm dialog) rejects the request
Who can approve? Users with ADMIN or TEACHER role. The Approvals link only appears in the navbar for these roles.

Email Invitation → Account Setup

Admin Only
  1. Admin opens Invitations → clicks Invite User
  2. Enters recipient's email and selects a role (Teacher, Student, Staff)
  3. Backend sends a one-time secure link to that email
  4. Recipient clicks the link → redirected to Account Setup page
  5. They enter their name and password — account is immediately ACTIVE
  6. Invited user can log in right away (no approval needed)
Resend & Revoke: If the link expires or user misses the email, Admin can resend. Admin can also revoke an invitation before the user accepts it.
